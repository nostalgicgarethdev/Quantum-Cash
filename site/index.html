quantumcash.network

A devnet you can read.

Bitcoin-style UTXOs, a 12,500-tick proof-of-history slot, and a W-OTS-style signature on every spend. One Go process. Nothing here is a public network.

UTXO ledger

Coins live in unspent outputs. A spend reveals a 2,144-byte public key and a signature. Inputs must cover outputs.

Proof-of-History

Each slot is a sequential SHA-256 chain. Transaction ids are mixed in at fixed ticks. Verifiers replay it. This is not Solana's validator.

Hash-based signatures

The signature code is a teaching W-OTS over SHA-256, w=16. It is not SLH-DSA, ML-DSA, or RFC 8391 WOTS+. Each key signs once.

Run a node

git clone https://github.com/nostalgicgarethdev/Quantum-Cash.git
cd Quantum-Cash
go build -o qcash ./cmd/qcash
./qcash wallet new -w alice.json
MINER=$(./qcash wallet address -w alice.json)
./qcash node -addr 127.0.0.1:8545 -miner "$MINER"

In a second terminal: ./qcash wallet send <address> 12.5 -w alice.json -memo gm. The default bind without -addr is every interface. Prefer localhost.

Honest limits

  • One node. No peers, no fork choice, no reorgs.
  • Toy proof-of-work. The devnet default is 16 leading zero bits.
  • Teaching-grade signatures, unaudited. A key that signs twice can leak.
  • QCASH has no value. A seller of QCASH is not this project. An old Waves token reused the ticker. This repository is not that token.
